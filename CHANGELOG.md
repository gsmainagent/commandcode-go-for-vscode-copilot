# Changelog

## Unreleased

### Features

- **Requests go through a vendored `commandcode-proxy`.** The upstream protocol — the CLI-shaped request envelope, the device fingerprint, and the startup lifecycle handshake — is now a child process pinned at commit `ce5a2177` rather than code in this repository. The proxy presents requests as ordinary CLI traffic and is maintained upstream, so a protocol change is tracked there instead of here. It starts on an ephemeral port in ~150ms, takes the API key per request rather than from a file, and is stopped on deactivate.
  - Note that the request envelope is built by the proxy from a synthetic device profile. The upstream CLI always sends `config.workingDir` while VS Code may run with no folder open, so a working directory has to come from somewhere; the same profile also keeps a real local path, branch name and commit subjects out of every request. As a result the git context an earlier build collected is no longer sent upstream.
- **Vendor the proxy by commit, with a verified digest.** `tools/vendor-proxy.mjs` fetches a pinned git commit and records the entrypoint's SHA-256 in `vendor/commandcode-proxy/VENDOR.json`. `npm run verify:proxy` re-checks the on-disk copy offline, and `npm run package` runs that check before shipping, so a modified copy fails the build rather than reaching a user's machine — it carries the API key.
  - Vendoring deliberately does **not** use the npm package `commandcode-proxy@1.0.0`. That artifact is a different, earlier lineage: it targets CLI `0.26.3`, reads the key from `~/.commandcode/auth.json` (requiring a local CLI install), and contains no fingerprint, no lifecycle handshake and no `x-project-slug`. The repository's own `v1.0.0` tag is three months newer than the npm artifact of the same name.
- **Dynamic model list.** The picker is built from the Go plan page instead of a compiled-in allowlist, so models added upstream appear without an extension update. The page decides membership (53 models) and supplies each model's name, capabilities, price, intelligence score and context window.
- **Canonical ids from Go-supported sources.** The plan page links models by slug (`kimi-k3`) while the Generate API requires `moonshotai/Kimi-K3`; a bare slug is refused with `403 Model/provider not recognized`, and the vendor prefix cannot be derived. Ids resolve in order from the compiled registry, the cached mapping, and the CLI reference page (`docs/reference/cli/models`, 51 of 53 on its own, 52 combined with the registry). Matching absorbs the differences between the two spellings, including the billing qualifiers the plan page drops (`tencent-hy3` on the page, `tencent/hy3-paid` in the ids). A slug nothing resolves to keeps its bare slug and still appears — hiding a model the plan states is the worse error.
- **Vendor-declared capabilities.** The plan page's `Caps` column states each model's capabilities verbatim (`Capabilities: Text input, Vision, Reasoning`). That is the source of truth for `imageInput` and the thinking selector, resolved strongest-evidence-first: live plan page, then the compiled table in `src/capabilities.ts` (generated from that same page), then conservative defaults.
- **Price and intelligence in the picker.** Per-million-token input / output / cache-read / cache-write rates and the plan page's `Intelligence` score are parsed and shown in the model tooltip. Off-peak rates are displayed and peak rates (which the page hides in an `aria-label`) are shown alongside, with the peak window described — one name per model, never two entries for the same model at different hours.
- **Self-refreshing list.** The merged list is stored with a timestamp and refetched once it is older than `catalogRefreshMinutes` (default 30), so a newly published model reaches the picker on its own. Queries inside the window are served from storage.
- New settings: `planBaseUrl`, `cliReferenceBaseUrl`, `catalogBaseUrl`, `generateBaseUrl`, `catalogRefreshMinutes`, `modelSource` (`dynamic` / `static`), `modelBlacklist`, `maxContextTokens`.
- **Request allowances in the picker tooltip.** A second table on the plan page states `Requests / 5 hours`, `/ week` and `/ month` per model. It is parsed by its own header (`parseQuotaTable`) and joined onto the model rows through the display name, which is the only identifier the two tables share — normalised with the same `slugifyModelKey` the rest of the module matches on, because keying on the raw lowercased name attached only 13 of the 41 available allowances. Three models state fractional counts (`64.7`, `93.3`, `81.4`) and they are kept verbatim: each doubles in step with the integer rows, so they are real per-window counts rather than thousands. The table covers 41 of the 53 models on the plan, and a model it omits shows no allowance rather than a zero, since absent means the page said nothing, not that the model is unlimited. A row whose figures cannot all be read is dropped rather than recorded partially.
- Unit tests (`npm test`, 89 cases) covering plan-page parsing and column mapping, quota-table parsing and the allowance join, CLI-reference id extraction, slug mapping, refresh policy, token-budget splitting, per-model output ceilings, tool-call stream reassembly, picker taglines, and capability precedence.

### Changes

- **The OpenAI shape is now the wire format.** The proxy exposes `/v1/chat/completions`, so the extension's OpenAI-shaped messages are sent as-is. The second conversion hop is gone: no `input_schema`, no `{ type: 'tool-call' }` parts, no envelope, and the AI SDK part union with them. Image parts moved from a non-standard `parts` field into the standard `content` array, which is what OpenAI expects on the wire.
- **Deleted the direct client.** `src/client/core.ts` (505 lines) reimplemented SSE parsing, the envelope and event mapping that the proxy now does, and had no remaining callers. `src/provider/context.ts` went with it. The error layer stayed: it turns HTTP and network failures into actionable messages regardless of transport. Net −900 lines.
- **The list rests on the plan page again, after an API-first detour.** An intermediate build made `GET /provider/v1/models` the foundation because it is JSON and returns canonical ids. That was wrong on the Go plan: `docs/provider` states "Every plan except the Go plan has API access", and its request endpoints answer `403 Your Go plan doesn't include API access`. Only the model-list GET is ungated, so depending on it was a bet that an excluded endpoint stays open. It is now the last-resort id source, consulted only when a slug is still unresolved, and every one of its failure modes is silent.
- **Plan-page parsing hardened against three real failures.** An off-peak tooltip no longer leaks into the model name; the `Caps` label no longer collides with the `input:` price label; and price columns are resolved from the table header, because only 15 of 53 rows name their price column at all while the rest say `N context price bands`. Price coverage went from 5/53 to 53/53.
- A table without a `<thead>` is rejected outright rather than parsed partially, since the context and intelligence columns cannot be identified without header labels.
- **Metadata degrades instead of disappearing.** When the plan page is unreachable, the previous snapshot's capabilities, prices and scores are replayed — all 53 retained in testing. With no cache, the curated registry is used. Either way a source outage never empties the picker and never silently strips vision support.
- **No entitlement probing.** A model your account cannot call fails when selected instead of being hidden. Probing cost one request per model on every cold start, and a misconfigured probe endpoint silently marked the entire catalog callable. A cold start is now two to three requests and a warm start is zero.
- **Token budgets are one value, used twice.** The number reported to Copilot and the number sent as `max_tokens` both come from `src/token-budget.ts`.
- Removed settings that no longer do anything: `plan`, `usePlanPage`, `verifyAvailability`, `reverifyDays`, `modelIdOverrides`. The plan slug is fixed to `go`; this extension supports the Go plan only.
- npm scripts no longer require `bun`.

### Fixes

- **Picker taglines are localised.** The curated registry held 34 hardcoded English one-liners while the rest of the tooltip went through `t()`, so a Chinese UI showed English taglines beside Chinese labels. They now live in both dictionaries in `src/i18n.ts` as `model.detail.<slug>` keys, resolved at display time by `modelTagline()` — the registry cannot resolve them itself because `i18n.ts` imports the VS Code API that the unit tests do not provide. A key that fails to resolve renders no tagline rather than the raw key, and tests assert every key exists in both dictionaries and matches its own model id, so a mistyped key fails the build instead of quietly dropping a line.
- **`max_tokens` respects each model's own ceiling.** The endpoint accepts 200000, but every model declares its own maximum and refuses anything higher with a deterministic 400 — `Range of max_tokens should be [1, 131072]`. Sending one constant for the catalog was right for the four models it had been measured against and wrong for the rest, and the refusal was then retried as if it were transient: five attempts over about fifteen seconds for an error that could not change. Scanning the Go catalog found three tiers — 65536 (`Qwen3.6-Max-Preview`), 131072 (`Qwen3.8-Max`, `Qwen3.7-Flash`, `Qwen3.7-Plus`, `Qwen3.7-Max`) and 200000 for the rest. `src/output-ceiling.ts` records the measurements, keyed by exact id because the Qwen family is not uniform (`Qwen3.8-27B` accepts 200000).
  - An **unmeasured model gets the lowest confirmed ceiling**, not the endpoint maximum. The catalog gains models between refreshes and their ceilings are not published, so assuming the maximum is the assumption that broke. A ceiling is raised only after a request at that value succeeds.
- **Tool-call names are no longer concatenated.** The proxy repeats a tool name on more than one stream delta, so appending each fragment produced `get_weatherget_weather` and Copilot would have called a tool that does not exist. Arguments still accumulate; a name is taken from the first fragment that carries one.
- **ZDR header spelling corrected.** Requests sent `x-cmdc-zdr`, which the vendor does not document; the documented name is `x-cmd-zdr`. Whether the old spelling was silently ignored could not be established — every model tried accepted both — so the documented name is used on the assumption that it is the one that means something.
- **Output budget no longer over-reported.** A previous build reported the full context window as `maxOutputTokens` while sending a different value upstream. Probing put the *endpoint* ceiling at 200000: `200001` is refused with `400 BAD_REQUEST — Too big`. Large models get that full ceiling for output and the remainder for input; smaller windows take a quarter so input keeps the majority. Input and output can no longer sum to more than the model's real window. (Corrected later the same day: 200000 is the endpoint limit, not a per-model one — see the per-model ceiling fix below.)
- **Capabilities no longer inferred from probes.** An earlier build measured vision by sending each model a solid-red PNG and got 10 models wrong, every Kimi among them: the probes went through an OpenAI-compatible proxy that does not forward image parts, so every model looked text-only. The hand-written registry annotations had also drifted from the vendor's on 20 of 51 models. Both are replaced by the plan page's declaration.
- The model list is cached in extension global state, so it survives a restart and normal use makes no requests.
- Every id source failing at once still lists every plan model: 52 of 53 appear under their bare slug rather than being dropped. Selecting one fails, which is the intended tradeoff.
- A plan page that parses into fewer than 20 rows is treated as a layout change and ignored, so a partial parse cannot silently mark models text-only.

## 0.1.0 (2026-08-17)

### Features

- Initial release — Command Code Go for VS Code.
- Pulls live model list from `GET /provider/v1/models` and exposes them in the Copilot Chat model picker.
- Streaming Chat Completions over the OpenAI-compatible `/provider/v1/chat/completions` endpoint.
- BYOK API key stored in VS Code SecretStorage.
- Per-model thinking effort selector (`none`, `low`, `medium`, `high`).
- Vision-capable models receive image parts natively (no proxy required).
- Optional zero-data-retention header (`x-cmd-zdr: 1`).
